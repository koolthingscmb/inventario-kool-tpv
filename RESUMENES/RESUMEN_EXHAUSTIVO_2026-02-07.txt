File: kool_tpv/modulos/impresion/ticket_generator.py
----------------------------------------------------------------------
Propósito:
- Construir ticket en texto plano con ancho fijo (WIDTH = 42), alineado en columnas.
- Exportar método generate(config, ticket_data, items, cliente_data) -> str.

API pública y detalles:
- TicketGenerator.__init__(self, width=42)
- _format_currency(val) -> '123.45'
- _safe_get(item, keys, default) -> helper para extraer campos con nombres alternativos
- generate(config, ticket_data, items, cliente_data=None) -> str

Secciones generadas:
- Encabezado (nombre, dirección, NIF) centrado.
- Info venta (Factura simplificada o ticket, fecha, hora, cajero, número).
- Cuerpo: headers (Cant | Articulo | PVP | Total), cada línea formateada, truncando nombres largos.
- Resumen IVA: iteración sobre iva_desglose para listar cada tipo % y cuota.
- Resumen totals: subtotal, IVA total agregado, TOTAL (en mayúsculas).
- Tabla de pagos: columnas fijas (9,10,10,10) sumando 42; soporta "Efectivo", "Tarjeta", "Mixto" y casos de devuelta/cambio.
- Fidelización y tesoro: si cliente_data o tesoro_data, imprimir desglose.
- Pie: texto centrado con aviso "I.V.A Incluido".

Cambios y mejoras hechos (06/07/07):
- Manejo robusto de entradas faltantes (None, '', '0').
- Soporte de pagos mixtos: imprime dos filas separadas (Efectivo/Tarjeta) con importes correspondientes; si importe_efectivo o importe_tarjeta ausentes, toma 0.
- Corrección de f-strings problemáticos: usar f"{valor:<{width}}" sin espacios dentro del especificador.
- Ajuste para nombres que contienen saltos de línea: sanitized_name = name.replace('\n', ' ').replace('\t',' ')
- Soporte para cantidades decimales (ej. 0.5 unidades) y redondeo de línea según regla de negocio (actual: multiplicación directa con Decimal y truncado a 2 decimales).
- Añadido try/except interno en generate para capturar excepciones y devolver string de error controlado (evita crash en impresión).

Casos edge-case cubiertos:
- item sin precio -> se marca como 'N/A' y total calculado si existe otro campo total.
- item sin cantidad -> cantidad por defecto 1.
- iva_desglose como lista o dict -> normaliza a lista de tuples.

Recomendaciones:
- Añadir tests unitarios que validen ancho de línea y que ninguna línea exceda width.
- Validar outputs en diferentes codificaciones (utf-8, latin1) si la impresora lo requiere.

En la jornada del 2026-02-06 se consolidaron los flujos de cobro y persistencia (mixto y desglose de pagos) y se mejoró la generación de tickets (TicketGenerator) junto con una impresión simulada. Decisiones técnicas clave vigentes:
- Seguir usando `Decimal` para todos los cálculos monetarios en memoria y serializar a string al persistir (evitar float en SQLite).
- Generar tickets en texto plano con ancho fijo (42 chars) para facilitar debugging y simulación en terminal; proporcionar adaptadores para ESC/POS/ PDF cuando se requiera impresión física.
